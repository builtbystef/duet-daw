## Goal

Duet DAW is a native C++ desktop application that a producer can genuinely make music in — record, arrange, edit, and mix audio and MIDI — with an AI collaborator built into the session as a first-class participant, not a bolted-on chatbot. The first milestone is a complete DAW core (the contents are in node kimula's closing note) plus one genuinely useful AI interaction, growing from there toward a professional-grade instrument. There is no strict timeline; completeness was chosen over an early cut-down release.

**Licensing posture (2026-08-07):** the project starts as open source, with the potential to become a commercial product later. Every choice of technology, library, and service must keep that path open — prefer permissive or dual-licensable dependencies; a copyleft-only dependency with no commercial-license option forecloses a commercial edition and needs explicit justification. **Settled at node a3p83b (2026-08-08):** Duet ships under AGPLv3 (LICENSE in repo root, ADR 0001), and no outside code contributions are accepted — no PRs, no CLA — so every line stays relicensable for a future closed edition. If contributions ever open, a CLA comes first.

**AI data strategy (2026-08-07):** the Collaborator perceives the project through deterministic analysis tools the DAW owns, never through audio. The model is given structured text — key, tempo, per-track loudness, spectral balance, MIDI as note lists, instrument identity, arrangement structure — computed by native code and delivered as tool results. The model does not listen to a rendered mix and does not infer musical facts a DSP routine can measure. The reasoning: a tool that measures is right every time and is cheap to test, where a model asked to hear is unverifiable and unevidenced — no vendor claims musical reasoning over audio (node sdfjqh). This makes the **project data model the entire AI surface**: every tool reads from it, so its scriptability is an AI requirement, not only an engine one. It also makes the tool vocabulary a first-class design artifact alongside the edit vocabulary settled at node hll1mo (now node u24m3x). Recorded as ADR 0002 at the spec session (o3mgk1).

**Stack settled so far:** JUCE 9 as the application foundation (node 1hn16k) and Tracktion Engine as the engine layer (node lf8tnt) — both dual-licensed, so the open-source build is free and a commercial edition is a purchase-and-subscription decision rather than a rewrite. The engine's `Edit` is a `juce::ValueTree`, which is what makes the AI data strategy above practical: the project data model is traversable, observable, undoable and serialisable out of the box. Duet's own edit vocabulary sits as a layer in front of the engine (node skb4tp), which is also what keeps a future engine swap from being a rewrite. The agent loop is **pi (MIT), run as a sidecar process bundled into the DAW install** (node lxwoas; mechanism refined at the spec session o3mgk1): a minimal Node host embeds pi's SDK and speaks one newline-delimited JSON-RPC 2.0 protocol with the DAW over a local socket — prompts, streamed events, cancellation, and tool calls all cross that one seam (ADR 0003). Users authenticate model-provider subscriptions through pi or enter an API key; no provider is treated specially in the model picker. The tool contracts transfer unchanged to a native C++ loop, so the sidecar is swappable if it disappoints. Milestone one ships the full Collaborator shape — commentary plus Proposals in every edit domain, with the complete Duet Loop mechanics — with fail-fast offline behavior (node lxwoas).

**Plugin hosting (node hvv3nn, 2026-08-07):** VST3 comes free through JUCE; **CLAP is hand-built as a `juce::AudioPluginFormat` + `juce::AudioPluginInstance` pair registered into Tracktion's public `PluginManager::pluginFormatManager`** — the same seam Tracktion itself uses for its non-JUCE Cmajor format. Both formats then reach the `Edit` as ordinary `ExternalPlugin`s, so sidechain, state, automation, bus layout, editors, latency and undo come free, with two conditions: the CLAP wrapper must expose a sidechain as a *second JUCE input bus* (Tracktion's `canSidechain()` is a pure channel-count test), and it must marshal `clap_plugin_state` over the partial-read/write loop CLAP's `stream.h` mandates. Hosting is **in-process**; isolation comes from **out-of-process scanning**, which Tracktion already implements in full and Duet only has to switch on. **Narrowed at node u24m3x's session (2026-08-08): milestone one hosts VST3 only.** VST3 comes essentially free through JUCE and Tracktion's `ExternalPlugin` — a switch, not a build — while the CLAP host must be hand-written from scratch, because no usable CLAP hosting library exists at any licence. The whole deferred cost was CLAP-specific, so CLAP moves to milestone two and nodes 89jlz1 and 00yd6o closed unresolved. Shipping VST3 from day one keeps the `AudioPluginFormat` seam exercised in production rather than designed-for and never run, so adding CLAP later is registering a second format into a path that already works. hvv3nn's design stands unchanged and is not reopened.

**Tool Vocabulary (node u24m3x, 2026-08-08):** the Collaborator perceives the project through **seven read-only tools** — `list_tracks`, `get_arrangement`, `get_midi`, `get_track_analysis` (with an optional bar range), `get_plugin_chain`, `get_automation`, and `estimate_audio_content`. The sufficiency principle is **provenance, not UI parity**: every fact is read from the project data model, measured from rendered audio by a documented routine, or explicitly marked as an estimate. Estimated values arrive as structural wrappers (`value`/`source`/`method`/`confidence`) while read and measured values stay bare scalars, so a guess can never be mistaken for a fact — by the model or, via the panel's estimate-marking, by the producer. **Tools measure, the model reasons**: no diagnostic tools, no pre-seeded state, no selection or transport tools (those ride in the run's opening context). The deterministic layer is hand-written DSP for loudness, spectrum, dynamics, key, monophonic pitch and onsets, plus **Basic Pitch via ONNX Runtime + RTNeural for polyphonic transcription** — the one ML dependency, proven in JUCE C++ by NeuralNote (Apache-2.0) and droppable if the runtime causes build trouble. Analysis runs on demand, cached per track and invalidated by edits; a multi-second first call is accepted because runs are non-blocking.

**Toolchain (node psmj4y, 2026-08-08):** **CMake ≥ 3.22** (JUCE 9's declared floor; Tracktion's own 3.15…3.20 is lower and does not govern), `project(... LANGUAGES C CXX)` because JUCE hard-errors without a C compiler, **Ninja Multi-Config** via a checked-in `CMakePresets.json` at schema v3, with `CMAKE_EXPORT_COMPILE_COMMANDS ON`. **C++20 is set explicitly on Duet's own targets** — a real trap, not a formality: Tracktion's module headers declare no `minimumCppStandard` at all, so JUCE's module machinery falls back to `cxx_std_11` for them while JUCE's own modules declare 17. Nothing in the dependency graph enforces C++20; every Tracktion example sets it by hand, and so does Duet. **Dependencies come through `FetchContent`, every pin a full commit SHA**, with **JUCE declared before Tracktion** so Tracktion's `if(NOT TARGET juce::juce_core)` guard skips its vendored submodule — which is both how Duet gets JUCE 9 instead of the pinned 8.0.13, and how it avoids Tracktion's SSH submodule URL breaking anonymous CI clones. `TE_ADD_EXAMPLES OFF`. ONNX Runtime is consumed as the **prebuilt release tarball behind a hand-written IMPORTED target**, never `find_package` — the shipped config package is broken (it points at `lib64/` and `include/onnxruntime/`; the tarball ships `lib/` and flat headers), verified by building against it — and the whole polyphonic-transcription path sits behind one CMake option so u24m3x's escape hatch is a `-D` flag. RTNeural takes its default Eigen backend (vendored in-tree; xsimd is a submodule). Tests are **Catch2 v3** for Duet's own code. Milestone one is **Linux x86_64 only**, floor **GCC 13** — set by `<format>`, which reached libstdc++ only at 13.1 — with Clang 18 on libstdc++ as the secondary compiler. Deliberate flags: `JUCE_JACK=1` (headers only; JUCE `dlopen`s libjack, which is what makes the PipeWire path work), `JUCE_PLUGINHOST_VST3=1`, `TRACKTION_ENABLE_TIMESTRETCH_SIGNALSMITH=1`, and `JUCE_USE_CURL=0`/`JUCE_WEB_BROWSER=0`/`JUCE_PLUGINHOST_LADSPA=0` to drop three Linux dev packages. **A premise retired: hosting VST3 needs no SDK download** — JUCE 9 bundles the VST3 SDK under `juce_audio_processors_headless`. CI is **GitHub Actions on a pinned `ubuntu-24.04`** (free and unlimited on public repos; `ubuntu-22.04` is ruled out for having no GCC 13), Debug + Release, **no compiler cache** — a cold uncached full JUCE+Tracktion Linux build-and-test measured 4–11 min on Tracktion's own 4-core runners, and upstream runs 31 such jobs nightly with no caching at all. Sanitizers split into two nightly configs, ASan+UBSan and TSan+UBSan, because the toolchains forbid combining ASan and TSan; TSan is schedule-only (Tracktion's TSan job took 146 min). A `checks-pass` gate job is the single required status check, and a3p83b's no-contributions decision deletes the whole CLA/fork-PR layer. Ready to become an ADR and to close `l1gtax`.

**AI-area spec (node o3mgk1, 2026-08-08):** published as issue **js437t** ("The Collaborator — milestone-one AI collaboration", label `spec`), covering hll1mo, sdfjqh, lxwoas, u64tso and u24m3x, with ADR 0002 (deterministic tools, never audio), ADR 0003 (pi-SDK sidecar behind a socket protocol), and the AI seam recorded in ARCHITECTURE.md. It settles the socket protocol methods, the seven tool contracts, the `propose` tool with the enumerated edit-operation vocabulary, the Proposal state machine (pending/accepted/rejected/superseded plus stale; element-level cherry-pick), mechanical estimate marking via a per-run ledger, single-active-run lifecycle, and the real-time safety rules. Milestone-one riders decided there: conversation and Proposals are in-memory per app session (persistence waits on rquzdc), and accepting a Proposal lands as one undoable action (mechanism at skb4tp). Implementation slices come from `/create-issues js437t` — build the sub-issues, never the spec issue.

**Edit vocabulary & shared undo (node skb4tp, 2026-08-09):** settled by headless prototype (branch `prototype/undo-vocabulary`), user-verified through an interactive GUI. Duet's edit vocabulary is **one layer whose interface exposes zero engine types** (opaque uint64 refs wrapping `EditItemID`, time as plain seconds/beats) — the spike's harness and GUI compiled against it without a single `tracktion::` type, which is the engine seam drawn concretely. Each op is expressed once and always passes the Edit's `UndoManager`; `insertAudioClip` pins source paths absolute centrally. **Actions are the only transaction boundary**: `performAction(name, ops)` calls `beginNewTransaction(name)` and deliberately does not seal afterwards, so the engine's deferred undo-tracked writes (the async clip re-sort, `ClipOwner.cpp:125`) merge into the action that caused them. A producer gesture and an accepted Proposal both go through it, so undo parity and one-step collapse hold by construction; a **Proposal is data until accepted**, so rejection leaves zero trace. Rolling-transport undo/redo is glitch-free with zero xruns. Hazards recorded in the closing note: naked ops merge into foreign transactions or land in unnamed timer-sealed steps; `Edit::flushState()` writes with the UndoManager (saving pollutes history/kills redo — feeds rquzdc); undo/redo permutes ValueTree property order (comparisons must canonicalize); the transport dying seconds after first headless playback is the DeviceManager's one-time async device-list rebuild, not an undo problem. Ready to become an ADR; feeds the foundation spec (86t5lu).

**Persistence & project shape (node rquzdc, 2026-08-09):** settled by headless prototype (branch `prototype/duet-persistence`, 27/27 checks). Duet's own data lives in a **DUET child tree under `edit.state`** — one file, atomic save, persists automatically — with per-write undo visibility: nullptr-UM writes are invisible to producer undo, through-UM writes revert with it. `EditItemID` is a safe durable key (IDs survive save/reload identically; reassignment happens only on actual in-file ID collision, and the engine keeps the original's ID). Saving uses a **snapshot save, never `flushState`**: copy `edit.state`, apply the `IDs::parameters` blobs to the copy with no UndoManager, write the copy — because `flushState` clears the redo stack exactly when automation has driven a parameter away from its explicit value (Tracktion's own save has this flaw; the snapshot dodges it, proven). Versioning: the DUET tree carries `duetSchemaVersion`; migrations run oldest-first on load before anything reads the tree; a newer-than-app file is refused with the needed version named. A project is a **folder** (edit file + `audio/` subdir, project-relative paths). Duet must set its application version in the Engine's PropertyStorage (the spike stamped `appVersion="Unknown"`). Ready to become an ADR; feeds the foundation spec (86t5lu).

**Foundation spec (node 86t5lu, 2026-08-10):** published as issue **b1j3me** ("The Foundation — DAW-core substrate for milestone one", label `spec`), covering kimula, 1hn16k, lf8tnt, psmj4y, ddp1qt, hvv3nn, skb4tp and rquzdc, with ADR 0004 (edit vocabulary, Actions as the only undo boundary) and ADR 0005 (DUET tree, snapshot save, project folder); ARCHITECTURE.md now records the module shape (`duet_model` / `duet_persistence` / `duet_app`) and AGENTS.md carries the settled check commands (issue l1gtax closed). Gaps closed by interview there: the thread model (message thread is the sole writer of the project model; no Duet code on the audio thread; workers for analysis/thumbnails/renders; Collaborator socket marshals to the message thread), the Audition mechanism (apply-and-revert on the real Edit via nullptr-UndoManager writes, revert exactness by canonicalized digest, manual save auto-reverts a live Audition and autosave skips its tick during one), save policy (explicit save + 5-minute autosave to an in-folder recovery file), and undo depth 200. The producer-facing UI was split out as its own area (grill s11o4w → prototype r4m858). Implementation slices come from `/create-issues b1j3me` — build the sub-issues, never the spec issue.

**RT-audio testing (Frontier sharpening, 2026-08-10):** sharpened into nodes by interview. The trust boundary: Tracktion Engine is trusted outright; only Duet's own audio code is under test — the built-in instruments and effects (the one place Duet code runs in the audio callback) and the worker-thread analysis DSP. RT *safety* ("no allocations, no locks, no syscalls in the callback") stands as coding standards + review, with CI enforcement via RealtimeSanitizer under research at node bd11an — whose deliverable includes writing the RT-safety section of CODING_STANDARDS.md either way. Audio *correctness* is offline render + feature assertions (measured properties of the render), never golden-file comparison; render determinism is verified by prototype at node xciphe. The analysis DSP validates against synthetic reference signals only (ground truth by construction, no licensing) for milestone one. Area spec node: ox1trt.

## Frontier

<!-- In-scope questions that you can see, but cannot phrase sharply yet. They become nodes as the roadmap advances. -->

- What the Collaborator carries across sessions (project memory, taste, prior feedback). Within-session conversation is settled at node hll1mo; the storage substrate is settled at node rquzdc (the DUET tree, persisting with the edit file). What is carried, and how it is summarized or aged, stays open — milestone one keeps conversation in-memory per app session (spec js437t).
- Milestone-two sequencing: when each feature deferred from milestone one lands — comping, punch-in, loop-recording, recorded automation modes (touch/latch/write), curved automation segments (linear-only in milestone one, spec 535bbo; the data model stays curve-ready), **CLAP hosting** (deferred 2026-08-08 at node u24m3x's session; the design is settled at hvv3nn, the open questions — including the CLAP thread-contract rules for a host — are preserved in the closing notes of 89jlz1 and 00yd6o), LV2/AU hosting, pre-fader sends, external hardware routing, a session/clip-launch grid view, concurrent Collaborator Task Runs (milestone one runs one at a time, spec js437t), and **out-of-process plugin hosting** — deferred out of milestone one at node hvv3nn, which found neither JUCE nor Tracktion has any such facility and no permissively-licensed implementation exists to copy. Building it means shared-memory audio transport plus a blocking semaphore round-trip inside every audio callback per bridged plugin, and it costs embedded plugin editors (Carla, the one open implementation, makes bridged GUIs transient rather than reparenting them). Milestone one gets its isolation from out-of-process *scanning* instead, which Tracktion already ships.
- Corpus benchmarking of the analysis DSP on annotated real-music datasets (GiantSteps key set and kin) — deferred at the RT-testing sharpening (2026-08-10) until a routine disappoints in use. An accuracy score is a tuning benchmark, not a regression test; dataset licences are unchecked.
- Distribution, updates, and code signing per platform. The sidecar decision (node lxwoas) adds: bundling pi's standalone binary per platform, and its unmeasured disk/startup footprint (not measured in ddp1qt: the skeleton did not include the sidecar; measure at the first sidecar integration).
- Windows-port audio backend: whether to ship ASIO at all, and on which terms. The free ASIO SDK route is GPLv3 and would infect the whole application; a closed Windows build needs Steinberg's proprietary agreement, whose text is not retrievable from Steinberg's own site (node 1hn16k, Unresolved). Not milestone-one work — Linux ships first, and JUCE's WASAPI backend covers Windows including exclusive and shared-low-latency modes.
- The commercial edition itself: what it is and how it is sold. The licence and CLA half closed at node a3p83b; the product half stays here, with a working assumption from that session — same app as a closed edition, solo developer, tier pair JUCE Indie ($800 perpetual, to $300k) + Tracktion Engine Indie ($35/mo, to $200k organisation-wide gross revenue including funding). Pre-commercial checklist from a3p83b, all requiring Tracktion sales rather than research: whether perpetual Tracktion licences can be bought (subscription lapse ends the right to distribute shipped binaries), and how the organisation-wide revenue cap applies to an individual. Mitigation accepted: form a legal entity before shipping any closed binary, and contact Tracktion sales then.

## Out of scope

<!-- Items excluded on purpose. The list only grows. One line for each item, with the node's ref if it was a node. An item never moves back in. -->

- A shadow-Edit copy as the Audition mechanism — rejected at node 86t5lu (2026-08-10): a second live Edit doubles every plugin instance and the model's memory, and A/B means swapping entire playback graphs mid-transport. Apply-and-revert on the real Edit (nullptr-UM writes, digest-verified revert) chosen instead.
- Sending audio to the LLM — rejected 2026-08-07 under the AI data strategy: no vendor claims musical reasoning over audio (node sdfjqh), and every audio-derived fact worth having is measurable deterministically. A DSP routine that measures beats a model asked to listen.
- Generative music models — rejected 2026-08-07: no MIDI/symbolic generation, no text-to-music, no stem or audio generation. The Collaborator reasons and proposes edits; it does not synthesise material. Node sdfjqh additionally found that most candidate weights are CC-BY-NC and unshippable under the licensing posture regardless.
- Local-model fallback for the Collaborator — rejected 2026-08-08 at node lxwoas: the Target Producer's hardware cannot run a useful local model, and a silent quality drop would be worse than an honest failure. An unreachable backend fails fast with a visible offline state. Local inference could return only as a deliberate, separately designed offline mode, never as a fallback.
- Mobile or web versions — the product is a native desktop app, decided at the goal level.
- Qt as the application foundation — rejected at node 1hn16k: no MIDI at all, no JACK or ASIO audio backend, no plugin hosting, LGPLv3 relink obligations, and an explicit ban on mixing open-source and commercial Qt in one project.
- Dear ImGui as the application foundation — rejected at node 1hn16k on its own README: it targets tools and debug UIs "as opposed to UI for the average end-user", and accessibility is stated as not supported.
- A custom stack (Skia or NanoVG + SDL3 + RtAudio + libremidi) as the application foundation — rejected at node 1hn16k: all permissive and technically viable, but it hands a solo developer every windowing, text, IME, and plugin-hosting problem at once. NanoVG is additionally unmaintained by its own README.
- Carla as the plugin-hosting layer — rejected at node 1hn16k: the only unified CLAP+VST3 hosting abstraction found, but GPLv2+, which the licensing posture rules out.
- Ambient/unprompted AI observation — rejected at node hll1mo: the Collaborator never speaks or acts uninvited; it fails the taste bar (interrupts flow), and anything it would catch is available on demand by asking for feedback. The only unprompted signal is a finished task run.
- Autonomous AI mutation of the project — rejected at node hll1mo: every Collaborator change enters the project only as a Proposal the producer accepts; nothing changes silently.
- Writing the audio engine from scratch on bare JUCE — rejected at node lf8tnt. JUCE 9 supplies device I/O, format readers/writers, disk streaming, real-time primitives and (verified in source, against the common belief) automatic audio plugin delay compensation in `AudioProcessorGraph` — but it ships no mixer semantics at all (no fader, pan, send, bus or meter node exists), no time-stretch, no metronome, no automation-curve engine, no tempo/musical-time playhead, no session document model, no streaming sampler, and no offline render driver. All of that is milestone-one work, none of it is what differentiates this DAW, and Tracktion Engine's ValueTree-based `Edit` is a better fit for the AI seam than a scratch model would likely have become.
- Native Wayland windowing — rejected at node hvv3nn: JUCE 9 has no Wayland peer at all (`juce_gui_basics/native/` is X11-only, the peer takes an X11 `::Window`, and the only "wayland" strings in the tree are XWayland *workarounds*), and CLAP's own `gui.h` states that on Wayland "embed is currently not supported, use floating windows". Duet runs under XWayland. Should JUCE ship a Wayland peer, it arrives as an upgrade, not as roadmap work.
- `jatinchowdhury18/juce_clap_hosting` as the CLAP hosting dependency — rejected at node hvv3nn. It is the only CLAP-as-`juce::AudioPluginFormat` implementation and it is MIT, but it is dead (last commit 2022-10-06, predating JUCE 8 and 9), self-described "super-alpha", and leaves MIDI, state, GUI, latency, thread-check, render and tail unimplemented. Useful as a reference reading, never as a dependency.
- Subclassing `tracktion::engine::Plugin` directly for CLAP — rejected at node hvv3nn as the alternative to the `AudioPluginFormat` seam. It needs only six pure virtuals, but forfeits everything `ExternalPlugin` already does generically: parameter/automation binding, state persistence into the ValueTree, bus layout persistence, programs, latency, editor hosting and KnownPluginList integration all become hand-written. `EngineBehaviour::createCustomPlugin` is documented as a fallback for plugin *types*, not as a format seam.
- Outside code contributions — rejected at node a3p83b (2026-08-08): no PRs are accepted, so no CLA exists and every line of Duet stays the maintainer's own, relicensable for a closed edition. Bug reports and issues stay welcome. Reopening contributions requires introducing a CLA first; the reverse door (un-relicensing accepted code) does not exist.
- Rubber Band, SoundTouch and Elastique as the time-stretch backend — rejected at node lf8tnt on licensing. Rubber Band is GPLv2 with a paid commercial alternative and is incompatible with AGPLv3 JUCE without going commercial on both; SoundTouch is LGPL-2.1; Elastique requires an external commercial licence. Signalsmith Stretch is MIT, header-only, and already bundled with Tracktion Engine.
- Showing raw tool-call traces to end users — rejected at node u64tso (2026-08-08): task runs display rotating friendly status phrases instead; tool-call visibility is development-mode information only.
- A dedicated persistent "Collaborator is offline" UI state — rejected at node u64tso (2026-08-08), refining lxwoas: backend failure surfaces as a plain transient error line in the conversation. Fail-fast, nothing queues, DAW fully usable stay as decided.
- Diagnostic tools in the Tool Vocabulary (`find_masking`, `check_gain_staging`, `detect_duplicate_parts` and kin) — rejected at node u24m3x (2026-08-08): every one is a musical opinion hard-coded in C++ that competes with the model rather than feeding it, and fod077 showed the models find masking, diff duplicated parts and compare crest factors unaided. Tools measure; the model reasons.
- Pre-seeding project state into the Collaborator's system prompt — rejected at node u24m3x (2026-08-08): a second copy of the truth that goes stale mid-run and silently caps project size. The model starts blind and asks, so everything it knows is in the trace.
- aubio, libKeyFinder, Gist and Essentia as the deterministic analysis layer — rejected at node u24m3x (2026-08-08) on licence: GPL-3, GPL-3, GPL-3 and AGPL-3 respectively. There is no permissively-licensed C++ MIR library at all, which inverts the usual intuition — the licence-clean options are the ML ones (Beat This MIT, Basic Pitch Apache-2.0), and the DSP algorithms must be hand-written regardless.
- Beat and tempo detection — rejected at node u24m3x (2026-08-08): the project owns its tempo map, so a DAW is told its tempo rather than detecting it. Beat This solves a problem Duet only has for off-grid imported audio.
- A special warning or refusal flow for Google free-tier API keys in the model picker — dropped 2026-08-08 at the spec session (o3mgk1): no provider is treated specially. sdfjqh's data-use finding stands as research; it no longer drives product behavior.
- vcpkg and Conan as the dependency manager — rejected at node psmj4y (2026-08-08): neither has a port or recipe for Tracktion Engine or RTNeural at all, and vcpkg's JUCE port is stuck at 8.0.7 (JUCE 8) while its ONNX Runtime port is five minors behind upstream. Two of five dependencies simply absent settles it before the versioning question arises.
- Git submodules as the dependency mechanism — rejected at node psmj4y (2026-08-08): Tracktion's own `.gitmodules` points at JUCE over **SSH** (`git@github.com:…`), which breaks anonymous recursive clones in CI without a `url.insteadOf` rewrite, and RTNeural needs `--recursive` for xsimd. Supplying JUCE ourselves through FetchContent dissolves the problem rather than working around it.
- `find_package(onnxruntime CONFIG)` against the prebuilt tarball — rejected at node psmj4y (2026-08-08), verified empirically: the shipped config package points at `lib64/` and `include/onnxruntime/` while the tarball ships `lib/` and flat headers, so configure fails outright. Duet declares its own IMPORTED target.
- Ubuntu 22.04 (and any GCC ≤ 12) as a supported build environment — rejected at node psmj4y (2026-08-08): `std::format` reached libstdc++ only at 13.1, three releases after the rest of the C++20 library, and the `ubuntu-22.04` runner image tops out at GCC 12.3.
- `CMAKE_CXX_CLANG_TIDY` as the lint mechanism — rejected at node psmj4y (2026-08-08): it runs clang-tidy on every translation unit CMake compiles, which for a project vendoring JUCE and Tracktion means linting both upstream trees. Lint is driven from `compile_commands.json` over an explicit list of Duet's own sources instead.
- A sidecar file for Duet's project data — rejected at node rquzdc (2026-08-09): works mechanically, but costs two files to keep in sync, no undo coupling, and torn state if one write fails. The DUET child tree gives one file and an atomic save.
- `flushState` as Duet's save path — rejected at node rquzdc (2026-08-09): it flushes every plugin unconditionally and writes the parameter blob through the UndoManager whenever automation has diverged a parameter, clearing the redo stack. The snapshot save replaces it.
- Single-file projects — rejected at node rquzdc (2026-08-09): a project is a folder (edit file + audio/ subdir), so recordings and imports travel with it.
