# 0006 — Audio testing: feature assertions over golden renders, RTSan as the RT-safety backstop

Context: Duet's own code in the audio path — the built-in instruments and effects, plus the worker-thread analysis DSP — needs correctness and real-time-safety enforcement in CI, and offline renders proved bit-exact run-to-run on the CI host (roadmap node xciphe), which makes golden-file comparison tempting. Decision: Tracktion Engine is trusted outright and only Duet's code is under test; audio correctness is asserted on measured features of an offline render (pitch, onsets, RMS/spectral change) with domain tolerances, never on golden files, fingerprints, or raw sample equality against stored output — the one sample comparison allowed is a within-process render-twice determinism canary; analysis DSP validates against synthetic reference signals whose ground truth is known by construction; RT safety ("no allocations, no locks, no syscalls in the callback") is a coding standard enforced by review, with RealtimeSanitizer (Clang 20.1.8+, its own third nightly config, `[[clang::nonblocking]]`-annotated entry points exercised by offline render) as a dynamic backstop, not proof. Reason: bit-exactness holds only within one host and would break silently across compilers, CPUs, and platforms, while feature assertions state the behavior that must survive those changes; RTSan checks only executed paths, so review remains the enforcement and the sanitizer catches regressions (roadmap nodes bd11an, xciphe).

Amendment (2026-08-19, issue vhl9d0): a measured offline render does not stand in for the playback graph. The engine builds one graph to render an Edit and another to play it, and they route differently — a track with no output and no destination is summed into the master by the rendering one and wrapped in a node that blocks its audio by the playing one — so every feature assertion above is blind to what a producer actually hears, which is how a group bus that swallowed everything routed into it shipped through a green suite. Decision: audibility and headroom are asserted on the playback graph, through the model's meters (`Session::outputPeakDb`, `Session::trackPeakDb`) fed by `Session::playWithoutAudioDevice`, which runs that graph block by block with no audio hardware and so runs in CI; the offline render keeps everything else it was chosen for.
