# 0004 — One edit vocabulary, Actions as the only undo boundary

Context: the producer and the Collaborator edit the same Tracktion `Edit`, and the engine's own transaction timer (350 ms, mouse-up-coupled) plus its deferred undo-tracked writes make naked ValueTree mutations land in foreign or unnamed undo steps. Decision: every project change goes through one engine-type-free vocabulary layer whose ops are callable only inside `performAction(name, ops)` — which opens a named transaction and deliberately never seals it — and an accepted Suggestion is just ops through the same path. Reason: undo parity between producer and Collaborator, one-step collapse of multi-op Actions, and absorption of the engine's deferred writes all hold by construction instead of by discipline; proven in the `prototype/undo-vocabulary` spike (roadmap node skb4tp).
